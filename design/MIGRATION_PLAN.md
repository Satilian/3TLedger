# Перенос страниц на UI-kit

## Порядок работы

- Выполнять страницы последовательно, размеры каждой страницы: 1440 → 768 → 393.
- Каждая страница хранится в `design/pages/<page>.pen`; все её размеры — в одном файле.
- Сохранять существующий дизайн, состав блоков и данные. Исправлять дефекты и согласовывать оформление с UI-kit.
- Использовать компоненты, layouts и токены из `design/ui-kit.lib.pen` через существующее подключение библиотеки по примеру Dashboard.
- Недостающие повторно используемые компоненты и токены добавлять в UI-kit без дублирования. Уникальное содержимое размещать в слотах и overrides.
- После проверки перенесённого размера удалять его исходный макет из UI-kit, предварительно проверив зависимости.
- Не менять остальные размеры заранее. После изменений библиотеки проверять уже завершённые макеты на регрессии.
- `user-profile.pen` не менять. Код приложения и публичные API не входят в работу. Автоматические тесты не добавлять.

## Контроль и коммиты

1. Выполнить один подпункт и необходимые для него изменения UI-kit.
2. Проверить ссылки на компоненты и токены, отсутствие случайных дублей и overrides.
3. Просмотреть снимок макета: выравнивание, переносы, читаемость, денежные значения, легенды, отсутствие наложений и непреднамеренного clipping.
4. Сохранить файлы, повторно прочитать результат, проверить завершённые размеры на регрессии.
5. Проверить Git diff и выполнить `git diff --check`.
6. Отметить выполненный подпункт `[x]`, записать изменения и результаты проверки в журнал ниже.
7. Создать отдельный коммит завершённого подпункта вместе с обновлением этого плана. Пользователь разрешил коммиты после каждого подпункта.
8. Продолжить следующий размер текущей страницы. После завершения страницы целиком остановиться для проверки пользователем. Push не выполнять.

Отметка `[x]` означает выполнение и проверку подпункта; наличие коммита указывается отдельно в журнале.
