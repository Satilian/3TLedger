# 3T Ledger Principles

> Every technical decision must support at least one of the three pillars:
>
> **Transparency**
> **Trust**
> **Trail**

---

# 1. Simplicity First

The simplest solution that solves the problem is preferred.

Complexity must justify itself.

---

# 2. Transparency by Default

Users should always understand:

- where data comes from;
- how it changes;
- why it changes.

Nothing important should be hidden.

---

# 3. Trust Through Verification

The system should minimize the need for assumptions.

Information should be verifiable.

---

# 4. Every Change Has History

Nothing important should disappear.

Every modification should leave an audit trail.

Deleting information is discouraged.

Archiving is preferred.

---

# 5. Privacy Matters

Transparency never means exposing private information.

Visibility is always controlled by permissions.

Transparency exists inside the allowed scope.

---

# 6. User Owns Their Data

Users should always be able to:

- export data;
- backup data;
- migrate data.

No vendor lock-in.

---

# 7. Offline Friendly

Whenever possible:

- read offline;
- write offline;
- synchronize later.

---

# 8. API First

Everything available in the UI should also be available through APIs.

---

# 9. Open Architecture

Modules should be replaceable.

The system should encourage extensions rather than forks.

---

# 10. Build for Decades

Avoid decisions that only optimize today's problems.

Think long-term.
